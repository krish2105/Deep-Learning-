# Master Prompt Pack

Prompts for rebuilding, extending, or continuing SENTINEL-CXR with Claude Code.
Paste one into an empty folder (Prompt 0) or into this repository (all others).

Each prompt states the **constraints that actually bind**, because those are what an
agent gets wrong. Vague prompts produce plausible code that fails on the free tier.

## Prompt 0 — Rebuild the entire system from an empty folder

```
Build SENTINEL-CXR: a chest radiograph triage system whose defining property is that
it abstains rather than guessing when it cannot meet a statistical coverage guarantee.

CONTEXT
Final Group Project for Deep Learning (MAIB AI 114), S P Jain Dubai, Prof Anshul Gupta.
Group: Krishna Mathur AS25DXB018, Atharva Soundankar AS25DXB020, Yash Petkar AS25DXB021.
Graded on: Research Depth, Innovation, Application of Techniques, Presentation.
Learning outcome E (ethics/fairness) is assessed ONLY in this project, so a fairness
audit is a graded requirement, not an appendix. Outcome D requires generative AI to be
genuinely integrated, not mentioned.

THE THESIS
Most medical DL fails to deploy because it is confident about everything, including
inputs outside its training distribution. Build three layers of refusal:
1. Convolutional VAE gate — reject non-radiographs BEFORE classification.
2. Uncertainty decomposition — separate epistemic (model ignorance, justifies
   abstention) from aleatoric (irreducible ambiguity, does not).
3. Split conformal prediction — distribution-free finite-sample marginal coverage.
   Abstain when the set is empty-with-near-misses, oversized, or epistemically uncertain.

HARD CONSTRAINTS — these determine the architecture, do not design around them later
- Render free tier: 512 MB RAM, 0.1 CPU, spins down after 15 min. PyTorch DOES NOT FIT.
- HF Spaces free tier: 2 vCPU, 16 GB RAM, sleeps after 48 h, ~40 s cold start.
- Vercel free tier for the frontend.
- Render's free Postgres EXPIRES after 30 days — use Supabase instead.
- Gemini free tier: 15 RPM / 1000 RPD on Flash-Lite. Must work with NO key at all.
=> Three tiers: Vercel (UI) → Render (orchestration, NumPy conformal head, no ML
   framework) → HF Spaces (all PyTorch). Render keeps a quantised ONNX fast path and
   marks such responses "reduced" VISIBLY in the UI. Degradation is never silent.

DATA
NIH ChestX-ray14: 112,120 images, 30,805 patients, 14 labels.
CRITICAL: split by `Patient ID`, NEVER by image. The dataset averages 3-4 studies per
patient; splitting by image leaks follow-up scans across the boundary and inflates
every metric. Assert disjointness in code.
`Patient ID` + `Follow-up #` also give real longitudinal sequences — this is what makes
the RNN/LSTM component clinically meaningful rather than a syllabus box.
`Patient Age`, `Patient Gender`, `View Position` are the fairness strata.

BUILD
- apps/web      Next.js 15 App Router, TS, Tailwind v4, Motion, Lenis → Vercel
- apps/api      FastAPI, SQLAlchemy async, JWT, pure-NumPy conformal head → Render
- services/inference  PyTorch, torchxrayvision, Grad-CAM, VAE, LSTM → HF Spaces
- notebooks/    11 Colab notebooks, one per syllabus week
- Report (.docx) and two decks (.pptx) generated by scripts

DESIGN LANGUAGE
Radiographs are read on grayscale-calibrated monitors, so a colour cast over the image
is clinically wrong. Turn that into the identity: the interface is monochrome and
colour encodes ONLY doubt. Confidence IS chroma — a chip at 0.97 renders fully
saturated, drains toward neutral as confidence falls, and is achromatic plus a diagonal
hatch at the abstention threshold. The API computes the saturation value so UI and
backend cannot disagree. Light AND dark themes; the image viewer stays film-dark in
both, because you never read a radiograph on white.
Landing page gets full premium motion. The console does NOT — no Lenis, no parallax,
keyboard-first. Weighting the scroll of a tool someone uses forty times a day trades
their speed for our polish.

NON-NEGOTIABLE ENGINEERING
- The LLM never sees the image. It transforms structured model output into prose.
  Verify the OUTPUT: scan generated text for any of the 14 pathology names outside the
  supported set; on a hit, discard the generation, log it, use a deterministic template.
  Prompt instructions are a request; verification is the guarantee. Test adversarially.
- Add dropout to any model you train, or MC-dropout returns T identical passes and an
  epistemic uncertainty of exactly zero — a false claim of certainty.
- Use the finite-sample conformal correction ceil((n+1)(1-alpha))/n. Omitting it is the
  classic bug and silently under-covers.
- Store the SAME probability vector that decisions were made on. Storing raw scores
  while deciding on a posterior mean makes the UI show p above threshold next to
  "not included".
- Every surface states this is not a medical device.

VERIFY, DON'T ASSUME
Write tests that check the claims the system makes about itself: empirical coverage
>= nominal, BALD higher when samples disagree, a confident pneumothorax is STAT on
arrival, included == (p >= threshold) for all 14 labels, every pathology caught by the
grounding filter with no false positive on "massive" vs "Mass".

Ask me clarifying questions before you start.
```

## Prompt 3 — Frontend work

```
Work on the SENTINEL-CXR frontend in apps/web.

Design rules that are not negotiable:
- Monochrome interface. Colour encodes ONLY model uncertainty. The one exception is
  --stat red for critical triage, which is clinically mandated.
- Confidence is chroma: saturation encodes certainty, draining to achromatic + diagonal
  hatch at abstention. Never colour alone — the hatch, the label and the number all
  carry the signal, so it survives colour-blindness and greyscale print.
- The viewer stays film-dark in BOTH themes.
- Landing route: full motion, Lenis, one pinned scroll moment.
- Console route: NO Lenis, no parallax, no scroll-jacking. State-feedback motion only.
- prefers-reduced-motion respected in CSS and via useReducedMotion(). Lenis disabled
  for those users.
- Only transform and opacity animate. Responsive to 360 px. Visible focus rings.
  Contrast >= 4.5:1.
- Import from "motion/react", never "framer-motion".

Run `npm run build` and `npm run typecheck` before claiming completion.
```

## Working notes

Things that cost real time on this build, recorded so they cost less next time:

| Trap | What happens |
|---|---|
| TorchXRayVision label order | 18 pathologies in a different order. Map **by name**; position-matching mislabels every finding silently. |
| Pretrained model has no dropout | MC-dropout returns identical passes, epistemic = 0. Assert the layer count. |
| `-> None` on a 204 route | FastAPI infers `response_model=NoneType`, which is truthy, and the route errors at import. |
| Relative imports in the Space | HF runs `app.py` flat, so `from .models import` fails. Use absolute imports. |
| `.test` email domains | `email-validator` rejects special-use TLDs; test fixtures need a real-looking domain. |
| Hooks after an early return | `useTransform` inside JSX below a reduced-motion `return` breaks the rules of hooks. |
| Two thresholds, one trend | A trend computed from a different threshold than the findings list produces a report that contradicts itself. |
| Reward bonus in the RL env | Swamps the waiting cost; random, FIFO and heuristic all score the same and the benchmark is meaningless. |
