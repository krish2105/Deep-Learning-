# Deployment

Three free tiers. Roughly 25 minutes end to end. Order matters — the inference core
must exist before the API can point at it.

> This repository is **public**. Never commit `.env`. Every secret below is set in a
> platform dashboard, not in a file.

---

## 0. Prerequisites

| Account | Used for | Cost |
|---|---|---|
| [GitHub](https://github.com) | Source | Free |
| [Hugging Face](https://huggingface.co) | Inference core (16 GB) | Free |
| [Supabase](https://supabase.com) | Postgres + object storage | Free |
| [Render](https://render.com) | Orchestration API | Free |
| [Vercel](https://vercel.com) | Frontend | Free |
| [Google AI Studio](https://aistudio.google.com/apikey) | Gemini (optional) | Free |

Render's own free Postgres **expires after 30 days**, which would take the project
down before it is graded. Supabase is used instead, deliberately.

---

## 1. Inference core → Hugging Face Spaces

1. Create a Space: **New Space** → name `sentinel-cxr` → SDK **Docker** → **Free CPU
   basic (2 vCPU, 16 GB)** → Public.
2. Push the contents of `services/inference/` to it:

```bash
git clone https://huggingface.co/spaces/<your-username>/sentinel-cxr hf-space
cp -r services/inference/* hf-space/
cd hf-space && git add . && git commit -m "SENTINEL-CXR inference core" && git push
```

The `README.md` in that folder carries the YAML front-matter Spaces needs
(`sdk: docker`, `app_port: 7860`) — keep it at the root of the Space.

3. Wait for the build (5–10 min; it installs PyTorch), then check:

```bash
curl https://<your-username>-sentinel-cxr.hf.space/health
```

You should see `"classifier": "torchxrayvision:densenet121-res224-nih"` and a warning
that the VAE gate is untrained. That warning is expected until you run notebook 06.

**Note the URL.** The API needs it.

---

## 2. Database → Supabase

1. **New project**. Save the database password.
2. **Project Settings → Database → Connection string → URI**. Take the **pooled**
   connection on port **6543** — Render's free instance has very few connections and
   the direct port will exhaust them.
3. Convert the scheme for SQLAlchemy's async driver:

```
postgresql://...        →  postgresql+asyncpg://...
```

4. **Storage → New bucket** named `studies`, marked **Public**.
5. **Project Settings → API**: copy the project URL and the `service_role` key.

If you skip this entirely the API falls back to SQLite and stores images inline. That
works for a demo but does not survive a Render restart.

---

## 3. API → Render

1. **New → Blueprint**, connect this repository. Render reads `render.yaml`.
2. Set the variables marked `sync: false`:

| Variable | Value |
|---|---|
| `DATABASE_URL` | The `postgresql+asyncpg://…:6543/postgres` URI from step 2 |
| `INFERENCE_URL` | `https://<user>-sentinel-cxr.hf.space` from step 1 |
| `ALLOWED_ORIGINS` | `https://<your-app>.vercel.app` (add after step 4) |
| `SUPABASE_URL` | Project URL |
| `SUPABASE_SERVICE_KEY` | `service_role` key |
| `GEMINI_API_KEY` | Optional — template reports are used without it |

`SECRET_KEY` is generated by Render; leave it alone.

3. Deploy, then verify:

```bash
curl https://sentinel-cxr-api.onrender.com/api/v1/ready
```

`"mode": "full"` means the Space is warm. `"reduced"` means it is asleep — expected,
and the frontend handles it.

---

## 4. Frontend → Vercel

1. **Add New → Project**, import this repository.
2. **Root Directory: `apps/web`** — this is the step people miss; without it the build
   fails at the monorepo root.
3. Environment variable:

| Variable | Value |
|---|---|
| `NEXT_PUBLIC_API_URL` | `https://sentinel-cxr-api.onrender.com` |

4. Deploy. Then **go back to Render** and set `ALLOWED_ORIGINS` to your Vercel URL, or
   every browser request will fail CORS.

---

## 5. Deploying trained artefacts

The notebooks export three files. Until they are present the system runs on documented
defaults and **says so** — `/api/v1/ready` reports `calibration: false`, and the
Uncertainty tab shows that the coverage guarantee is not in force.

| Notebook | Produces | Goes to | Effect |
|---|---|---|---|
| `02_cnn_classifier` | `conformal_calibration.json` | `apps/api/artifacts/` | Coverage guarantee becomes real |
| `08_dqn_triage` | `dqn_policy.json` | `apps/api/artifacts/` | DQN replaces the heuristic |
| `11_fairness_ethics` | `fairness_report.json` | `apps/api/artifacts/` | Fairness tab populates |
| `06_vae_ood` | `vae.pth` | Space `weights/` | OOD gate activates |
| `02_cnn_classifier` | `densenet.pth` | Space, set `CLASSIFIER_WEIGHTS` | Your model replaces pretrained |

Commit the JSON artefacts (they are small); push model weights to the Space, not to
git — `.gitignore` blocks `*.pth` deliberately.

## Verifying the whole chain

```bash
API=https://sentinel-cxr-api.onrender.com

curl -s $API/api/v1/ready | jq

TOKEN=$(curl -s -X POST $API/api/v1/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com","password":"a-long-password"}' | jq -r .access_token)

curl -s -X POST $API/api/v1/studies/analyze \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@chest.png" -F "patient_ref=PT-001" | jq '{status, mode, triage_priority, abstained}'
```

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| First request takes 30–60 s | Render free tier spun down | Expected. Hit `/api/v1/health` to wake it. |
| `"mode": "reduced"` persists | Space asleep or `INFERENCE_URL` wrong | `POST /api/v1/wake`, then check the Space logs |
| CORS errors in the browser | `ALLOWED_ORIGINS` missing the Vercel URL | Add it in Render, redeploy |
| `too many connections` | Using the direct DB port | Switch to the pooled URI on 6543 |
| Vercel build fails | Root Directory not set | Set it to `apps/web` |
| Space build times out | PyTorch install is slow | Retry; the CPU wheel index is already pinned |
| Reports lack an LLM voice | No `GEMINI_API_KEY` | Expected — deterministic templates are used |

## Cost

Zero. The constraints that come with that — 512 MB on Render, a 48-hour Space sleep,
15-minute spin-down — are the reason the architecture is split across three tiers, and
are documented in the report as a design driver rather than an inconvenience.
